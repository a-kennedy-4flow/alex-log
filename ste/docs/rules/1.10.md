# Rule 1.10 — No regional, slang, or jargon words

**Statement** (Issue 9, page 1-1-12)
> Do not use regional, slang, or jargon words as technical nouns.

- **Applies to:** every technical noun of the text.
- **Needs:** glossary, as a deny list with a replacement for each entry.
- **Decidable:** yes against a deny list. A checker cannot recognize slang it has
  never been told about.
- **Code:** not implemented.

## Discrete form

```
check(text, deny_list L) -> [finding]

for each technical noun n of text:
    if L lists n:  finding(n, use: L.replacement(n), reason: L.reason(n))

pass = findings == []
```

`L` entries carry the reason, because the standard's argument is always the same
one and the writer needs it: only a small number of persons understand the word,
so it causes confusion and non-effective communication.

## Examples from the standard

| Word | Kind | Use |
| --- | --- | --- |
| choker | regional (logging, North America, Northern Europe, New Zealand) | cable |
| brick (a router) | technical slang in information technology | set the router to OFF |
| gear | jargon for tools and equipment | tools and equipment |

## Notes

- The deny list is the natural home for company style decisions that are not in
  ASD-STE100 at all, so keep the entries tagged with their source: `:ste_example`,
  `:company_style`, or `:project`.
- Rule 1.8 and this rule pull in the same direction from opposite ends: 1.8 says
  use the approved term, 1.10 says do not use the local one.
