# Rule 6.2 — Key words and key phrases

**Statement** (Issue 9, page 1-6-2)
> Use key words and key phrases to give your text a logical structure.

- **Applies to:** consecutive sentences and paragraphs of a descriptive text.
- **Needs:** text.
- **Decidable:** reporting only, but the report is a real measurement: whether each
  sentence shares a key word with an earlier one.
- **Code:** not implemented.

## Discrete form

```
check(text, structure S) -> [report]

for each paragraph p of a descriptive text:
    for each sentence s of p after the first:
        keys = content words and multi-word nouns of s
        if keys share nothing with the sentences before s, and s starts with no
           connecting word:
            report(s, :not_connected_to_the_text_before)

for each pair of key words (w1, w2) that name the same thing with different
wording:
    report(:terminology_changed, w1, w2)    # the same signal as rules 1.11 and 9.4

pass = always true; this rule reports
```

## The example, as a chain

| From | To | Shared key words |
| --- | --- | --- |
| sentence 1 | sentence 2 | system, show, pilot |
| sentence 2 | sentences 3 and 4 | localizer course, glideslope path |
| sentences 3 and 4 | sentence 1 | runway |
| sentence 5 | sentences 3 and 4 | runway |
| sentence 5 | sentence 2 | show(s) the pilot |
| paragraph 1 | paragraph 2 | deviation, data, localizer, glideslope |

## Notes

- The standard's own instruction is: "when you use key words and key phrases, make
  sure that you do not change them in your text". That is a lexical-overlap
  measurement, which is exactly what a checker can do well, so this rule is worth
  implementing as a report even though it never fails a text on its own.
- Connecting words and phrases (rule 4.4) are the other half of the same
  structure: key words carry the topic, connectors carry the relation.
