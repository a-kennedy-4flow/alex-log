# Rule 1.11 — One technical noun for one item

**Statement** (Issue 9, page 1-1-13)
> Do not use different technical nouns for the same item.

- **Applies to:** a whole document, not a single sentence.
- **Needs:** glossary with synonym groups, document.
- **Decidable:** yes, when the glossary groups the terms that name the same item.
- **Code:** not implemented.

## Discrete form

```
check(document, glossary G) -> [finding]

groups = {}
for each technical noun n in document, in order:
    g = G.synonym_group(n)
    if g exists: groups[g] = groups[g] + [(n, position)]

for each g with more than one distinct term used:
    finding(g, terms: distinct terms, use: G.preferred(g), positions: ...)

pass = findings == []
```

Because the check is over a document, its unit of work is a list of sentences or
a file, not a string. A string API can still answer it for the string that it
gets, which is what the standard's example is: three consecutive work steps.

## Example from the standard

Not STE:

```
1. Make sure that the servo control unit is in the open position.
2. Do the operational test of the actuator.
3. Disconnect the control unit from the test rig.
```

STE: use "actuator" in all three steps, because that is the technical noun that
the company, industry, or subject field approves.

## Notes

- Without synonym groups, a checker can still report a weaker signal: two terms
  that share a head noun and appear near each other ("control unit" and "servo
  control unit"). Report it as a question, not as a violation.
- Rule 9.4 is the same idea applied to whole sentences and work steps rather than
  to single terms.
