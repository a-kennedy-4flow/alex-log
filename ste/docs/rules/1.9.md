# Rule 1.9 — Short technical nouns

**Statement** (Issue 9, page 1-1-12)
> When you must select a technical noun, use one which is short and easy to
> understand.

- **Applies to:** a technical noun that you select yourself, because your
  company, industry, or subject field has no approved one.
- **Needs:** glossary, judgment.
- **Decidable:** the length half only. "Easy to understand" is a human decision.
- **Code:** not implemented.

## Discrete form

```
check(text, glossary G) -> [finding]

for each technical noun n of text that G does not mark as official:
    if word_count(n) > 3:  finding(n, reason: :too_long)   # counted per rules 8.7 and 2.1

pass = findings == []
```

The standard sets the length at "not more than three words", which is the same
limit as rule 2.1 for multi-word nouns. The difference is the subject: rule 2.1
judges the noun group in the sentence, rule 1.9 judges the term you invent when
no official term exists.

## Examples

| Verdict | Text | Why |
| --- | --- | --- |
| pass | `Remove the four screws (10) that attach the flange (15) to the cover (20).` | "screws", "flange", "cover" are sufficient because the index numbers and the illustration identify the parts |
| fail | `Remove the four stainless steel pan head machine screws (10) that attach the metallic machined flange (15) to the front housing cover (20).` | invented terms of five and three-plus words where index numbers already identify the parts |

## Notes

- The example shows the reason for the rule: when a part has an index number and
  an illustration, adjectives add length and no information. Where there is no
  illustration, the standard says to add one or two adjectives to help the reader,
  so a checker must not simply reward the shortest term.
- An official technical noun that is longer than three words is not a finding
  here; rule 2.2 says to write it in full and then shorten it.
